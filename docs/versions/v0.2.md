# v0.2 — the board

**Status: shipped.** `0.2.0`

Two changes, one theme: **make the day readable in a single glance, from the
couch, on the phone.**

1. A new home screen: **the board** — every field, one screen, no scrolling,
   grouped the way the rings are grouped, sized by how much each field matters,
   each tile drawn with the chart that suits it and tappable to log in place.
2. **Reachable from the phone** on the same network, because a dashboard you
   only open at a desk is a dashboard you stop opening.

Everything else in v0.1 stays as it is. This version adds a surface, it does not
rewrite the model.

---

## 1. The board

### What it is

A business-intelligence surface, not a form. One canvas fills the viewport: the
four rings and the day's score on the left, the four categories as quadrants on
the right, every field present as a tile. Nothing scrolls. Tiles shrink and grow
with the window instead of pushing content off-screen, so the picture is always
complete.

The board answers three questions without a single tap:

| Question                                   | Answered by                                  |
| ------------------------------------------ | -------------------------------------------- |
| How is today going?                        | the rings, the score, one focus line          |
| What have I done, what is still open?      | the tile states — lit accent vs. quiet track  |
| Where do I stand on the weekly targets?    | the gym / alcohol-free / clean tiles themselves |

### Layout

```
┌───────────────┬─────────────────────────┬─────────────────────────┐
│ RAIL          │ BODY                    │ MIND                    │
│               │  [sleep──────────]      │  [deep────────────]     │
│  four rings   │  [steps] [gym]          │  [learned] [read]       │
│  score        │  [alcohol] [greens]     │  [mood] [energy]        │
│  focus line   │  [outdoor] [creatine]   │                         │
│  5 of 14      │  [weight] [rhythm]      │                         │
│  7-day strip  ├─────────────────────────┴─────────────────────────┤
│               │ ATTENTION               │ PEOPLE                  │
│               │  [screen time───]       │  [real connection─────] │
│               │  [pickups] [clean]      │                         │
└───────────────┴─────────────────────────┴─────────────────────────┘
```

Weekly targets do not get a separate read-out: the gym, alcohol-free and clean
tiles *are* the weekly progress, each showing the week's count, its cells, and a
caption that names the target — never a daily zero.

- **≥ 1180 px** — the picture above: rail (≤ 290 px) with the seven-day strip,
  plus a 2×2 quadrant grid.
- **1024–1180 px** — the same grid, tiles tighten, the rail narrows and the
  strip steps aside for the tiles.
- **700–1024 px** — the rail becomes a top band (rings left, day and actions
  right), the quadrants stay 2×2 underneath.
- **< 700 px** — the four bands stack in one column, and sizes stop meaning
  height: `size 3` takes the full row, everything else takes half. Every field
  keeps its chart; importance on a phone is width, not row span, because there is
  no canvas to spare. That is 18 touch targets on one screen, which is the point
  of the whole exercise.

The board sets `height: calc(100dvh - var(--chrome-h))` and `overflow: hidden`,
and every grid row is `minmax(0, 1fr)`. Nothing can scroll; the layout absorbs
whatever height the device has. `.board` is a size container, so tile type is
clamped in `cqh` units and shrinks and grows with the viewport.

Tiles answer to their own size, not the window's, through container queries: a
tile shorter than 64 px drops its caption, shorter than 30 px drops its
decorative chart, narrower than 168 px drops its unit. The number is the last
thing to go, and it never goes.

### Tiles

One tile per thing you log — eighteen tiles carrying all twenty fields, because
two of them pair up well: bed and wake time share **Rhythm**, and the one-line
note rides inside **Learned**. A tile is a `<button>`: label, value, chart, and a
caption that says what the target is. Importance (`size` 1–3) drives how much
space a tile takes in its band; the chart drives how it reads.

| Category  | Tile             | Chart    | Size | Target           | Notes                              |
| --------- | ---------------- | -------- | ---- | ---------------- | ---------------------------------- |
| Body      | Sleep            | gauge    | 3    | 7–9 h            | the band, not the raw hours        |
| Body      | Steps            | bar      | 2    | 9,000            | closer is better, capped           |
| Body      | Gym              | segments | 2    | 2–3 / week       | weekly — three cells, not a zero   |
| Body      | Alcohol-free     | segments | 2    | 7 / week         | weekly, reframed positively        |
| Body      | Greens           | switch   | 1    | —                | yes / no                           |
| Body      | Outdoor          | bar      | 1    | 20 min           |                                    |
| Body      | Creatine         | switch   | 1    | —                | reminder, moves no ring            |
| Body      | Weight           | value    | 1    | your goal        | *optional* — never counted         |
| Body      | Rhythm           | clock    | 1    | regularity       | bed time + wake time in one tile   |
| Mind      | Deep blocks      | gauge    | 3    | 3 blocks         | the day's largest mind input       |
| Mind      | Learned          | switch   | 2    | —                | opens the one-line note with it    |
| Mind      | Read             | switch   | 1    | 10 min           |                                    |
| Mind      | Mood             | scale    | 2    | —                | the outcome the insights watch     |
| Mind      | Energy           | scale    | 2    | —                |                                    |
| Attention | Screen time      | gauge    | 3    | under 3 h        | lower is better, drawn as progress |
| Attention | Pickups          | bar      | 1    | 60               |                                    |
| Attention | Stay clean       | bar      | 2    | 30 days          | weekly — "25 days clean in 30"     |
| People    | Real connection  | gauge    | 3    | 1 conversation   | one is the bar, not five           |

Charts are deliberately few: **gauge** (radial, for the fields that carry a
category), **bar** (progress toward a target), **segments** (discrete counts),
**switch** (done / not), **scale** (five bars), **clock** (times), **value**
(a plain number). Seven chart types, one drawing routine each — enough vocabulary
to draw every field well and still look like one family.

Size follows the weight the field already carries in its category, so the board
and the rings agree about what matters: in attention, screen time is 3, stay
clean 2, pickups 1 — and they pack the band exactly, with no half-empty row.

### Tile states

Three, and they are the whole "what have I done" story:

| State   | Looks like                                                                    |
| ------- | ----------------------------------------------------------------------------- |
| `done`  | accent value, accent chart, hairline border, faint accent wash top-to-bottom   |
| `open`  | accent, but the chart is partial and the caption names the gap                 |
| `empty` | dashed border, value `—` in quiet ink, bare track, caption "Not logged yet"    |

A weekly tile in progress is `open` with its cells filled part of the way and a
caption that names the week — so a weekly field is never drawn as a daily zero.
Empty is quiet, never red. A tile you have not touched looks like a page you have
not written on yet, not like a failure.

### Logging from the board

Tap a tile → a small card opens over the board (bottom sheet on a phone) with the
field's prompt, its widget, and a context line — *"Yesterday: 7.5 h"*, prefilled
from `/api/prefill` exactly like the logging flow. Commit an answer and the tile
fills where it sits, the category ring moves, the score moves, the counter at the
top changes. A single-field tile closes the card the moment you answer; the
two-field tiles (rhythm, learned) keep it open with a **Done** button, and a
**Clear** button appears once there is something to clear.

Implementation notes, because they keep the project small:

- The card reuses the existing widgets (`web/js/log/widgets.js`) inside a `.quick`
  scope, so there is one slider, one counter, one toggle in the codebase.
- Saving is the existing `PUT /api/day/{day}` with `{field: value}`, which merges
  and returns the whole day payload. The board patches its tiles and rail with
  that payload, so what you see is what the server scores. No new endpoint.
- Tiles update in place rather than re-render, so the CSS transitions do the
  satisfying part: the gauge sweeps, the bar grows, the cell lights up.

`/log` remains the guided flow for the days you want to answer everything in one
pass, "in under thirty seconds". The board is for the other kind of day.

### The satisfying bit

The spec asked for this twice, so it is a requirement, not a finish:

- Every answer animates its own tile — a sweep, never a flash.
- The counter reads `5 of 14 logged today` (fourteen: weekly and optional tiles
  are not part of the day's count) and counts up as you go; when the last one
  lands it becomes `Every field logged.` with an accent dot.
- On completion the board changes character: `data-complete="true"` lifts the
  hairlines, gives each chart a soft accent glow, settles the rings once, and
  shows the closing line from the API under the score
  (*"Rings settled. That is a day worth repeating."*).
- No confetti, no emoji, no streak-on-fire. The reward is that the screen goes
  quiet and complete, and you did that in a minute.

### Deliberate omissions

- **The board is today only.** Past days keep living in the calendar and the day
  sheet; a writable past opens questions (retro-scoring) this version does not
  need.
- **The old home composition is retired.** The rings, the focus line and the
  seven-day strip all live on the board's rail now (the strip only where there is
  room: at 1180 px and below the calendar takes that job back). One home screen,
  not two. The demo page shows the board too — it is what "already lived in"
  looks like.
- **No drag-and-drop, no per-person tile layout.** The catalogue decides the
  order, and the catalogue is one file.

## 2. Reachable from the phone

- The server binds `0.0.0.0` by default (`PULSE_HOST` overrides), so any device
  on the same Wi-Fi can open the dashboard.
- On start, the console prints the LAN URL it can be reached at, and the browser
  still opens on the machine itself:

  ```
    Pulse — One glance. Four rings. One score.
    data:  /path/to/.data/pulse.db
    open:  http://localhost:8765
    phone: http://192.168.1.24:8765   ← same Wi-Fi, nothing to install
  ```

- The board is built mobile-first: 18 tiles, one screen, no scroll, thumb-sized.
- README gets a short "Use it from your phone" section, including the one line
  that keeps it local again: `PULSE_HOST=127.0.0.1 uv run pulse`.

This is a local-network surface with no authentication. It ships with the
dashboard because the dashboard's own README says: self-hosted, your data stays
in this folder — and now, on your own network, in your pocket.

## 4. Testing

- `uv run pytest`: 38 tests. New ones cover the board payload (every metric is
  reachable from a tile, sizes are 1–3, the state of an empty, a partly logged
  and a fully logged day, the weekly tiles, the optional weight, the habit name
  from settings, the weight goal, the note inside the learned tile), the LAN
  helpers, and a drift test that the version in the footer matches
  `config.APP_VERSION`.
- Playwright pass at 1440×900, 1280×800, 1024×768, 390×844 and 360×640: zero
  console errors, no scrollbar, and nothing inside the board poking outside it,
  checked by measuring every tile's box rather than by eye.
- The same pass answers a field in place and confirms the tile, the ring, the
  score and the counter all move, and that a fully logged day ends on
  "Every field logged."

## 5. Out of scope

Swipe gestures between log steps, Apple Health / Health Connect importers, light
theme, per-tile customisation, authentication. Not because they are bad ideas,
but because v0.2 has one job: make the glance complete.
