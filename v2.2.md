# v2.2 — log it on the board

**Status: planned.** `2.2.0`

v2.1 fixed *what the board shows*, and [v2.1.1](v2.1.1.md) fixed how much room
each field takes. v2.2 fixes *how you answer it*: the sheet goes away for
everything that does not need a keyboard. Drag the sleep knob, tap the third deep
block, flip the creatine switch — one gesture, saved, undone if you fumbled.

The rule for this release: **an answer should cost one gesture, and never a
modal.**

---

## The interaction, by shape

Each tile already draws the control; v2.2 makes the drawing live. The gesture is
the one the shape implies — no new vocabulary.

| Tile | Shape | Gesture on the board |
| ---- | ----- | -------------------- |
| Sleep | range | Drag the knob, or tap anywhere on the track to jump there. Saves on release. |
| Screen time | range | Same. |
| Pickups | range | Same. |
| Steps | bar | Tap anywhere on the bar to set that value; drag to scrub. |
| Outdoor light | bar | Same. |
| Stay clean | bar | Same, over the 30-day window. |
| Gym | segments | Tap a cell to set the week's count to it (tap the filled last cell to clear one). |
| Alcohol-free | segments | Tap the day you drank; the cell empties. Weekly, so the tile edits the week. |
| Deep blocks | blocks | Tap a block to set the count to that many. |
| Greens / Creatine / Read | switch | Tap the tile. The pill flips, the tile washes, the value turns accent. |
| Mood / Energy | scale | Tap a step. |
| Rhythm | night | Two inline time chips (`bed 23:10`, `wake 06:40`) using native time inputs, styled to sit in the tile. |
| Weight | trend | Drag across the sparkline — the axis is the last 21 days — with `↑`/`↓` nudging 0.1 kg. |
| Learned | switch + note | The switch flips inline. The note opens the sheet: it needs a keyboard. |

Everything else about a tile stays as it is in v2.1: the shape, the sizing, the
weekly rules, the optional rule for weight.

## Undo, not confirmation

Inline editing means accidental answers, so every write is reversible:

- A write is optimistic — the tile updates immediately, and the save is debounced
  (drag) or immediate (tap).
- A toast appears for four seconds: *"Sleep 7.5 h — Undo"*. Undo restores the
  previous value in the same shape, with no confirmation dialog anywhere.
- If the server refuses the write, the tile reverts to what it was and the toast
  says why. No red, no failure screen — the same product rule as v0.1.

Two guards against stray taps, in this order:

1. A tap that lands on a control *is* an answer — that is the point. There is no
   armed state to learn.
2. Undo is the safety net, and it is one tap.

## What still opens the sheet

Only two things, and both because they need a keyboard or a wider surface:

- **The learned note** — free text. Tapping the note chip opens the sheet *on
  that field only*, so the flow is: flip the switch on the board, tap the note,
  type, tap away.
- **The date** — the rail's day strip and the calendar stay as they are; the
  board is still today-only.

## Touch, pointer and keyboard

- Pointer events with `touch-action: none` on every drag surface. The board does
  not scroll, so a drag can never fight the page.
- Hit targets: 44px minimum for anything tappable, including the empty part of a
  track (a tap sets the value even if it misses the knob).
- Every control keeps its semantics: the range is a real
  `<input type="range">`-shaped control with `role="slider"`, cells and blocks
  are radio-like buttons with `aria-checked`, the switch is a `role="switch"`
  with `aria-checked`, and each tile's `aria-label` still reads
  *"Sleep: 7.5 h. Target 7–9 h"*.
- Arrow keys nudge the focused tile by one step; `Space`/`Enter` flips a switch
  or sets a scale.
- Haptics stay where they already are: a tick on a step change, a firmer tap on
  a commit.

## The phone

The board is the phone. On a small screen a finger covers the control it is
dragging, so:

- The value is mirrored above the control it belongs to (it already is — the
  value sits in the tile's top row) and stays visible while the knob moves.
- Drag thresholds are generous: a 1.2× the visual size for the pointer target.
- The pill, the cells and the blocks are all already at the container-query
  sizes that fit a thumb; nothing shrinks below 44px on the phone.

## Implementation notes

- One module, `web/js/components/inlineEdit.js`, owns the gesture → value →
  save path for every shape, so there is a single place where debounce, undo,
  optimism and reverting live. Tiles ask it to `bind(tile, control)`.
- The widgets in `web/js/log/widgets.js` keep their `onCommit` / `onLive`
  contract from v2.1. Inline editing is the board's own layer on top; the guided
  `/log` flow is untouched.
- `PUT /api/day/{day}` already merges a single field and returns the whole day
  payload, so the board patches itself exactly as it does today. **No new
  endpoint.**
- Undo keeps one previous value per field per write (a small map, cleared on
  navigation). Restoring is another `PUT` of the same field.
- `series` on the weight tile already ships in the payload (v2.1), so the trend
  axis needs no backend work.

## Test plan

- Unit: the board payload still holds for a day edited one field at a time.
- Playwright, at 1440×900 and 390×844:
  - drag the sleep knob → the value and the ring change, the server has it;
  - tap the third deep block → `deep_blocks` is 3;
  - tap the creatine switch → washed tile, accent value, saved;
  - tap a scale step → saved;
  - drag the weight history → saved, and the sparkline moves;
  - tap Undo → the previous value is back on the server.
- The five-viewport sweep from v2.1 still reports no scroll, no clipped tile and
  no console error.

## Out of scope

- No new fields, no new chart shapes, no scoring change.
- No editing of past days from the board (that is the calendar's day sheet).
- No drag-to-reorder tiles and no user-defined board layout.
