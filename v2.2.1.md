# v2.2.1 — open it up

**Status: shipped.** `2.2.1`

[v2.2](v2.2.md) made the cards the place you answer. This pass makes them the
place you *correct*: **In bed** now takes one clock instead of two, and every card
opens into a detail editor shaped to the field it holds.

Two rules held throughout:

- **The card still answers in one gesture.** The instrument is untouched. The
  editor is what opens when you click the card *around* the instrument — the same
  field, at the size a careful answer needs.
- **Nothing is stored twice.** You enter when you went to bed. The hour you got up
  is arithmetic: bed + slept.

---

## 1. In bed: one clock, not two

The card used to ask for a bed time and a wake time, then score how regular the
pair was. Two clocks that must agree are two chances to be wrong, and the sleep
duration was already logged next door.

```
   In bed  22:45  ✓                                    6/10
   ├───────────────▓▓▓▓▓▓▓▓──────┤
   21:00  22:00  23:00  00:00  01:00  02:00
   Up 06:30 · 7h 45m asleep
```

- **One entry.** `bed_time` only. `wake_time` is gone from the catalogue, the log
  flow, the demo and the board payload. Old rows that still carry it are simply no
  longer read — no migration, no data loss.
- **The wake is derived, never stored.** `wake = bed + sleep_hours`, computed in
  the payload. Change the sleep and the wake moves with it. No sleep logged yet?
  The card says *"Add slept hours for wake time"* and promises nothing.
- **The axis is where evenings actually happen:** **21:00 → 02:00**, five hours,
  six hour labels, 15-minute steps. A bed time outside it pins to the nearer edge;
  the head still shows the true clock, so the card never lies about the axis.
- **Your usual, drawn as a window.** A circular mean of the last 30 bed times
  (23:30, 23:45, 00:15, 23:00 averages to **23:37**, not 17:37) becomes a ±45
  minute band, with yesterday's tick beside it. This is the same regularity the
  ring scores, so the instrument shows exactly what is being measured.
- **The score is unchanged:** `sleep_regular` over the bed times of the last 14
  nights. Until four nights exist there is nothing to score — the card now shows
  **"—"** in the points slot instead of a dishonest `0/10`.

The 30-day lesson repeated itself here: a mean of clock times has to go the short
way round midnight, or the card quietly says your usual bedtime is late afternoon.

## 2. Every card opens

Clicking a card — its name, its number, its gap line, the space around the
instrument — opens it. Dragging or tapping the instrument still answers in place,
and still writes nothing but the field.

The head is a real `<button>`, so the editor is one **Tab** and **Enter** away; on
close, focus goes back to the card it came from.

| Card | What the editor offers |
| ---- | ---------------------- |
| Slept, Screen time, Pickups, Weight | A big readout, − / +, a full-width rail with the target band and yesterday's tick, an exact number field, and the field's presets (`6 h … 9 h`). |
| Steps, Outdoor light | The same, as a bar with the target tick. |
| Gym, Alcohol-free | **The trailing seven days**, one row per day with − / +. Any day can be edited, including past ones. |
| Clean day | All thirty days, each one a toggle. |
| Mood, Energy | The five words as full-width rows. |
| Deep blocks | None / One / Two / Three, drawn as blocks. |
| Greens, Creatine, Read | Two explicit answers. |
| Learned | Yes / No, and the note underneath. |
| In bed | The same 21:00–02:00 rail, plus an exact `time` field and the derived wake in words. |

- **Live save, no Save button.** Every control writes as it settles; *Done* only
  closes, and *Clear today* deletes today's answer (a `null` in the `PUT`, which
  the repository already treats as "remove this key").
- **The weekly grid is the trailing week, not Monday–Sunday.** This was the one
  real bug found in testing: the card counts the last seven days, so a Mon–Sun
  editor would have shown a different week than the one being scored. The editor
  now opens on exactly the seven days the score counts, today last.
- **Past days are writable from the board** — but only where the card is already a
  week grid (Gym, Alcohol-free, Clean day). Everything else edits today; the
  calendar's day sheet still owns arbitrary days.
- **Saves stay optimistic.** The board re-renders behind the sheet from the
  server's returned payload, so the card, the ring, the category count and the next
  best move all move while the editor is open.

## 3. The payload

Each card gained what the editor needs to draw the right control, so the editor
never guesses:

| Field | Meaning |
| ----- | ------- |
| `input`, `prompt`, `help` | The field's shape and the words above the control. |
| `presets`, `max` | The chips and the top of the rail. |
| `week_days` | The trailing seven days for the two segmented cards, oldest first. |
| `bed`, `wake`, `usual_bed`, `yesterday_bed` | Minutes past midnight; `wake` is computed. |

`week_days` is only sent for `gym` and `alcohol` — the clean-day card already
carries its thirty `days`, and booleans have no count to step.

---

## 4. What it taught

- **An editor and a card must count the same window.** The first build used a
  Monday-to-Sunday grid and summarised "2 of 2 days dry" beside a card that said
  "4 of 7 days". Both were true, and together they were useless. The fix was to
  hand the editor the score's own window rather than a calendar one.
- **Unscored is not zero.** A rhythm with three nights of data has no score; the
  card used to show `0/10` for it. Now it shows `—` and a tooltip, and the next
  move never prices a field the score cannot see yet.
- **Derived values should be derived everywhere.** Keeping `wake_time` in the
  payload "for the editor" would have re-created the second source of truth the
  whole change was meant to remove.

## 5. Verification

- **55 tests** (`uv run pytest`), including: wake derived from bed + sleep, the
  wake moving when the sleep changes, no `wake_time` in the schema, the
  around-midnight usual, the trailing seven `week_days`, and every editor field in
  the payload.
- **Playwright, at 1440×900 and 390×844**: every editor opened and wrote (rail,
  presets, exact field, stepper, Yes/No, note, scale, blocks, week rows, clean
  cells, bed rail and time field); a past-day write landed on that day and moved
  the week; dragging an instrument did **not** open the editor; a score-bar
  segment still only scrolls and pulses; `Escape` closed the sheet and returned
  focus to the card head; **zero console errors**.
- **Layout**: seven pages × seven viewports, no horizontal overflow and no console
  error; the home screen still fits without scrolling at 1440×900, 1920×1080 and
  2560×1440, and no card clips its contents.

## Known limits

- **The demo board is a picture.** Its cards are locked, so the editor does not
  open there — the demo shows the dashboard, not the editing.
- **Weekly cards edit the trailing week, not any week.** Older days belong to the
  calendar.
- **No undo yet.** Every write in the editor is live; reversal is still the next
  pass ([v2.3](v2.3.md)).
