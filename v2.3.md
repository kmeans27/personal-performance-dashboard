# v2.3 — undo, and the pointer pass

**Status: planned.** `2.3.0`

The board answers in one gesture and every card now opens into a detail editor.
Both write live. This pass makes a live write **safe**: one tap to take it back,
and controls that are easy to hit on a finger and a keyboard.

Nothing here changes what is logged or how it is scored.

---

## 1. Undo, not confirmation

Inline editing means accidental answers, so every write must be reversible:

- A write is optimistic — the card updates immediately, and the save is debounced
  (drag) or immediate (tap). This is already how `card.js` works.
- A toast appears for four seconds: *"Sleep 7.5 h — Undo"*. Undo restores the
  previous value in the same shape. No confirmation dialog anywhere.
- If the server refuses the write, the card reverts to what it was and the toast
  says why. No red, no failure screen — the same product rule as v0.1.

Two guards against stray taps, in this order:

1. A tap that lands on a control *is* an answer — that is the point. There is no
   armed state to learn.
2. Undo is the safety net, and it is one tap.

Undo keeps one previous value per field (a small map, cleared on navigation).
Restoring is another `PUT` of the same field — **no new endpoint.** Editors opened
from a card share the same map, so a change made in the sheet can be undone from
the toast after it closes.

## 2. Pointer, touch and keyboard polish

The behaviour exists; this release makes it defensible on a finger and a
keyboard.

- Hit targets: 44px minimum for anything tappable, including the empty part of a
  track (a tap sets the value even if it misses the knob). Card instruments are
  drawn at 14–104px depending on the layout mode, so the *visual* control may be
  smaller than the *pointer* target — the target is what gets the 44px.
- Pointer events with `touch-action: none` on every drag surface. On the phone the
  page scrolls, so a drag must not be stolen by a scroll — and a vertical scroll
  that starts on a card must not set a value.
- Every control keeps its semantics: a range is a `role="slider"` with
  `aria-valuemin`/`max`/`now`, cells and blocks are radio-like buttons with
  `aria-checked`, the switch is a `role="switch"`, and each card's `aria-label`
  reads *"Slept: 10.25 h. Target 7–9 h"*.
- Arrow keys nudge the focused control by one step; `Home`/`End` jump the range;
  `Space`/`Enter` flips a switch or sets a step.
- Haptics stay where they are: a tick on a step change, a firmer tap on commit.
- The detail editor keeps its focus trap, and returns focus to the card head it
  was opened from (both already true in v2.2.1 — this pass audits them at every
  breakpoint).

## 3. The phone

On a small screen a finger covers the control it is dragging, so:

- The value is mirrored above the control it belongs to (it already is — the value
  sits in the card's head) and stays visible while the knob moves.
- Drag thresholds are generous: 1.2× the visual size for the pointer target.
- The guided `/log` flow stays, one field per screen, as the alternative path. It
  is not a second *input surface* on Today; it is the same fields, one at a time,
  for when a card is too small to land on.
- The detail editor keeps its bottom-sheet shape below 860px, with the primary
  control focused on open.

## Test plan

- Playwright, at 1440×900 and 390×844:
  - drag the sleep track → the value and the ring change, the server has it;
  - tap the third deep block → `deep_blocks` is 3;
  - tap a Yes/No segment → washed card, accent value, saved;
  - tap a 1–5 step → saved;
  - change a value in a card's editor, close it, tap *Undo* → the previous value is back on the server;
  - a vertical swipe that starts on a card scrolls the page and writes nothing.
- The seven-page × seven-viewport sweep from v2.2.1 still reports no horizontal
  overflow and no console error.

## Out of scope

- No new fields, no new instruments, no scoring change.
- No drag-to-reorder cards and no user-defined board layout.
- The weight card stays a range around the goal; history lives in Trends, not on
  Today.
